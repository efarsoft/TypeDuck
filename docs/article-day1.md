# 造一个属于自己的公众号排版工具吧！0 开发基础，48 分钟

> 「造个轮子！排版鸭 TypeDuck」系列教程 · 第 3 篇
> 前置阅读：Day 0《开发工具与 AI 编程环境准备》（公众号内链接，发布后回填）

48 分钟。

从一个空文件夹，到一个能在浏览器里打开、能写 Markdown、能一键复制到公众号、样式一个不丢的排版工具。

而我全程没有写过一行完整的代码。我干的事是：提需求、做决策、验收、抓 bug。

这篇文章把那 48 分钟里发生的事——包括翻车的部分——都写出来。更重要的是，流程里的每一步（包括发给 AI 的原始提示词）都是可以照抄的：你不需要会写代码，照着走一遍，得到的就是一个你自己说了算的排版工具——免费、开源、数据不出浏览器。文末有我做完的线上版，可以直接玩。

---

## 一、先聊聊那个折磨所有人的问题

写公众号的朋友应该都经历过这个流程：

用 AI 帮你写完初稿，内容十分钟出来，质量还不错。然后你把 Markdown 粘到公众号后台，发现：

- 标题没有层次，全是一样大的黑字
- 代码块变成一坨没有颜色的等宽字体
- 配图位置乱了
- 引用块？不存在的

于是开始手动调格式。字号、行距、颜色、分割线……一篇两千字的文章，排版比写作用的时间还长。

中间那堵墙其实一直都在：

> **AI 吐出来的是 Markdown，但公众号编辑器吃的是富文本。**

市面上的排版工具不少，135、秀米、壹伴……但它们是为「手动排版时代」设计的，拖拽组件、调样式，一套下来比我写文章还累。

所以我决定自己造一个。顺便把造的过程记录下来，就是你现在看的这个系列。

---

## 二、开工前，先学会「指挥 AI」

很多人以为 AI 编程就是打一句「帮我做个工具」，然后坐等收货。试过的都知道，那样得到的是一个什么都想做、什么都做不好的四不像。

先交代下我的完整工作流，三个工具各管一段：

```
① DeepSeek —— 聊需求
   把「我想做个排版工具」聊成一份清晰的设计文档：
   功能边界、优先级、砍掉什么，都在这一步定

② ZCode —— 写代码
   AI 编程代理，直接在仓库里干活：
   建项目、写代码、跑构建、修 bug、提交 git

③ workbuddy —— 写文章
   你正在看的这篇，也是 AI 辅助写的：
   素材来自开发过程的真实记录，文风人工把关
```

三个环节里人是同一个人，但角色不一样：对 DeepSeek 我是产品经理，对 ZCode 我是技术负责人，对 workbuddy 我是编辑。

展开讲讲第一步。我和 DeepSeek 的开场白是这么写的，你可以直接抄（把方括号里的内容换成你的情况）：

```
我想做一个微信公众号排版工具，请帮我梳理需求。

目标用户：
- [用 AIGC 工具生成文章内容，产出是 Markdown 格式，但对 Markdown 语法并不熟悉]
- [手动排版公众号非常耗时间，经常为调格式头疼]
- [希望免费开源、数据全部留在本地，不想要服务端]

初步想法：
- 输入 Markdown，一键复制成公众号能用的格式
- 要有多个排版主题
- 后面可能加 AI 辅助写作
```

这段提示词没什么文采，但做对了三件事：

1. **讲清楚给谁用**——画像的每一行都会变成方案的硬约束：「数据留本地、不要服务端」直接砍掉了账号体系和云端架构；「不懂 Markdown」决定了产品必须做到贴进去就能用、所见即所得。AI 拿到的是约束条件，不是一堆形容词
2. **给足上下文**——用户痛点、技术底线、远期想法都摆出来，AI 不用猜
3. **开门见山要结论**——第一句就是「帮我梳理需求」，AI 不会跑题去写营销文案或者竞品分析，输出直接奔着能用的东西去

几个回合聊下来，「定位是什么、MVP 砍到哪、哪些功能后置」全都清楚了，最后落成一份带优先级（P0-P5）的开发文档。这份文档，就是后面 ZCode 开工的依据。

回到开工——跟 DeepSeek 把需求聊透之后，落到给 ZCode 的开发指令只有三句话：

> 1. 只做 Web 版 MVP，别碰桌面端
> 2. 本地优先，不要服务端、不要注册登录
> 3. 主题先做 4 套精品，不追求数量

ZCode 给出技术方案（Vue 3 + CodeMirror 6 + markdown-it），我看过没意见，它开工。

这一步的经验是：**AI 时代写代码的第一道门槛，不是语法，是把「我想要什么」讲清楚。** 边界越清晰，产出越准。需求在 DeepSeek 那里多聊十分钟，ZCode 那边就少返工一小时。

另外设计文档里原本列了一堆功能——AI 写作、热门榜单、图床、定时发布……我全砍了。MVP 只验证一件事：

> **从 Markdown 到公众号，样式零损耗。**

这件事成了，其他都是加分题；这件事不成，加一百个功能也留不住人。

## 三、最硬的骨头：「复制过去样式不丢」

整个工具的技术核心就一句话。

公众号编辑器有个要命的设定：**网页 CSS 的三大支柱它全清洗**——`<style>` 标签、class 属性、外部样式表，统统不认。

只留一条活路：写在元素身上的内联样式。

```
❌ 粘到公众号 → 被清洗
<style>.title { color: red }</style>

✅ 公众号唯一认的
<h1 style="color: red">标题</h1>
```

所以「一键复制」的本质，就是在 HTML 生成的最后一公里，把所有样式翻译成内联的，把所有 class 干掉。渲染管线长这样：

```
Markdown 源码
   ↓ markdown-it 解析
带 class 的 HTML（代码高亮全是 hljs-keyword 这类 class）
   ↓ DOM 后处理：注入内联样式 + 移除所有 class
全内联 HTML ──→ 预览区直接展示（所见即所得）
            ──→ 写入剪贴板 text/html 格式
```

有个设计我觉得做得对：**预览区和剪贴板用同一份 HTML。**

预览里看到什么，粘到公众号就是什么。不少同类工具的翻车就在「预览一套渲染、复制一套转换」，两套逻辑稍有偏差就变形。我们干脆只留一套。

代码高亮是最麻烦的部分。highlight.js 输出的着色全是 class，需要一张「class → 内联颜色」的翻译表，而且每个主题一张：浅色主题配 GitHub 配色，暗色主题配 Atom One Dark 配色。这样「极夜黑」主题的代码块复制到公众号，依然是暗色的。

## 四、翻车现场：AI 写的代码，AI 来审

只讲成功不讲翻车，那是广告。讲个真实的。

工具写完，我让 AI 把整个代码库静态审查了一遍。报告列了十几个问题，最狠的一个是数据丢失级别的。

当时的自动保存逻辑是「防抖 500ms」：停止打字半秒后保存一次。问题出在保存函数里——它保存的是「**当前打开的文档**」。

复现路径：

1. 在文档 A 里打字，触发 500ms 倒计时
2. 手快，第 300ms 就切到了文档 B
3. 第 500ms 倒计时结束，保存——保存的是 B
4. A 的改动从未落盘。这时刷新页面，A 的内容回退

你打的字就这么没了。而且平时完全无感，只有「编辑后立刻切换 + 恰好刷新」才触发——典型的上线两周后被用户骂才发现的 bug。

修起来不复杂：保存谁，在创建定时器那一刻就定死，别在执行时才去找「当前文档」。外加两道保险：切换文档前强制保存一次，页面隐藏或关闭前再兜底一次。

这个环节想分享的观点只有一个：

> **AI 写的代码也要审，而且 AI 可以审 AI。**

开发是 AI 写的，审查是 AI 做的，修复还是 AI 做的，一轮下来 9 个问题清零。人做的事变成三件：看懂报告、判断轻重、决定修不修。

「写代码」正在变成「审代码」。这个技能值得每个想做点东西的人练。

## 五、上线：3 分钟，一个能点的链接

代码写完只能算半成品，能被别人点开的链接才是产品。

部署用的 Vercel，免费：导入 GitHub 仓库、指定子目录、点部署，前后 3 分钟。之后每次 push，线上版自动更新。

现在可以直接玩：

> 🦆 **在线地址**：https://typeduck.vercel.app/
> 📦 **开源仓库**：https://github.com/efarsoft/TypeDuck
>
> 打开 → 左边写 Markdown → 右边换主题 → 点「复制到公众号」→ 粘贴后台。

手机上看的朋友可以先收藏，回头用电脑试一次：把任意一篇旧文粘进去换个主题复制出来，和原来的排版对比一下。

## 六、48 分钟背后的三件事

**1. 工具类产品的壁垒不是功能，是顺滑。**

这 48 分钟里大部分时间花在一件事上：让「复制 → 粘贴」这条路不掉链子。功能可以以后加，掉链子的第一印象没有第二次机会。

**2. AI 编程时代，人做的东西变了。**

五年前这个工作量以「人日」计，今天以「分钟」计。变化不是我突然会写代码了，而是流程变了：需求裁剪、约束表达、方案拍板、结果审查，人只做这四件事。

**3. 不用背八股文，也不用会算法，也能拥有一个为自己定做的工具。**

这 48 分钟里真正用到的能力是：把需求讲清楚、判断方案好坏、验收结果——传统编程那些「硬功夫」一样没上。这意味着什么？意味着「会不会写代码」和「能不能拥有自己的软件」这两件事，第一次脱钩了。

这套流程里的每一步——需求怎么聊、AI 怎么指挥、坑怎么提前抓——我会在这个公众号里一篇一篇展开讲。**关注「AI猿叔」，AI 开发的流程和经验，后面一篇不少。**
