# 从写完到见面，只差一个按钮——Day 5 让排版鸭学会送稿

> 「造个轮子！排版鸭 TypeDuck」系列教程 · 第 7 篇
> 前置阅读：Day 4《不知道写什么？Day 4 给排版鸭装上「选题引擎」》（公众号历史消息可查）

Day 4 结束时，排版鸭已经能从热点选题一路走到配图封面。但写作流程的最后一步还是手动的：复制 → 切到公众号后台 → 粘贴 → 传封面 → 填摘要 → 点保存草稿。

每天重复这套动作，像个搬运工。

Day 5 的目标：**把搬运自动化，把发布留给人工。** 同时给排版鸭一个正式的门面——官网上线。

---

## 一、一键发布到草稿箱

### 1.1 接口三件套

微信公众平台的草稿箱接口走的是标准 REST API，三步走：

| 步骤 | 接口 | 说明 |
|------|------|------|
| 获取凭证 | `GET /cgi-bin/token` | 拿 access_token，2 小时有效 |
| 上传封面 | `POST /cgi-bin/material/add_material` | 图片变永久素材，返回 thumb_media_id |
| 创建草稿 | `POST /cgi-bin/draft/add` | 标题+正文+封面+摘要 → 草稿箱 |

听起来简单，但每一步都有坑。我把踩过的记在下面。

### 1.2 第一个坑：IP 白名单

微信 API 有安全门槛——**只接受白名单里的 IP 发起的请求**。第一次调 `token` 接口，大概率会收到：

```json
{ "errcode": 40164, "errmsg": "invalid ip 203.xx.xx.xx, not in whitelist" }
```

这不是 bug，是设计。解决方法：把错误信息里给出的 IP 地址，加到公众号后台「基本配置 → IP 白名单」里。

排版鸭的处理方式：把这个错误翻译成人话——「IP 不在白名单：请把错误信息中的 IP 加进公众号后台」，用户复制 IP 去后台粘贴就行。**错误信息即操作指引**，这比弹个 error code 友好太多。

### 1.3 第二个坑：multipart 跨 IPC

上传封面的接口要求 `multipart/form-data` 格式。在网页里这很简单，`new FormData()` 就行。但排版鸭的桌面版走的是 Electron 的 contextBridge 通道——**FormData 无法通过 IPC 序列化**。

解法是手工拼 multipart 报文：

```typescript
function buildMultipart(file: { name: string; type: string; bytes: ArrayBuffer }) {
  const boundary = `----typeduck${Date.now().toString(36)}`
  const head = `--${boundary}\r\nContent-Disposition: form-data; name="media"; filename="${file.name}"\r\nContent-Type: ${file.type}\r\n\r\n`
  const tail = `\r\n--${boundary}--\r\n`
  // 拼 Uint8Array → ArrayBuffer → 通过 IPC 传给主进程 → net.fetch 发出
}
```

不是很优雅，但很可靠。这就是 Electron 开发的日常——渲染进程和主进程各有一套能力，桥接层需要你手工搬数据。

### 1.4 access_token 管理

微信的 access_token 有效期 2 小时，且**每天获取次数有限额**。排版鸭做了三层优化：

1. **内存缓存**：模块级 Map 存 token + 过期时间戳，提前 5 分钟刷新
2. **自动重试**：收到 40001/42001（token 失效）时，强制刷新一次再重试
3. **按需获取**：只在发布流程中请求，不预取

> 💡 **带走的知识点**：access_token 是微信生态的"通行证"，限额设计倒逼你做缓存。缓存策略的关键不是"缓存多久"而是"什么时候主动失效"——提前 5 分钟刷新是为了避免"用了刚过期的 token"这种边界情况。

### 1.5 发布前体检

发布不只是"点个按钮"，还需要检查清单。排版鸭在发布弹窗里内置了六项体检：

- 标题字数（≤64 字）
- 正文字数（≥30 字）
- 摘要（可空但有提示）
- 封面（必选）
- 外链图片计数（会自动转传）
- 图床配置状态

每一项用 ✓/⚠/✕ 标注，用户一眼看清哪些项要处理。这是从"功能完整"到"用户放心"的关键一步——**工具不仅帮你做事，还帮你确认事情做对了**。

### 1.6 正式发布永远人工

这是整个功能最重要的设计决策。

AI 生成的内容经过润色、改写、配图，最后到了草稿箱。从这里到读者的眼前，**必须经过人的审核和判断**。排版鸭不提供"自动群发"功能，也不打算提供。

原因写在了完成态的提示里：「去公众号后台预览确认后手动发布——发布这一步留给你，工具不替你拍板。」

这不是技术限制，是产品价值观：AI 负责效率，人负责判断。

## 二、官方正式上线

Day 5 的另一半工作，是给排版鸭一个正式的线上门面。

### 2.1 静态首页：零 JS 的 SEO 基础

原来的首页是 Vue SPA 的一部分——靠 JS 渲染内容，搜索引擎和 AI 引擎抓到的是空壳。

改法：首页拆成独立的 `index.html`，纯 HTML + CSS，**零应用 JS**（仅保留 3 行兼容重定向和微动效脚本）。编辑器成为独立的 `editor.html` 入口。

改动效果立竿见影：

- 百度爬虫和 GPTBot 能直接读到全部内容
- 首页全量 **24KB**（含 CSS），首屏秒开
- 加了完整的 SEO 基建：meta 标签、JSON-LD 结构化数据（SoftwareApplication + FAQPage）、robots.txt、sitemap.xml、canonical

### 2.2 FAQ 区块：GEO 的正确姿势

GEO（Generative Engine Optimization）是让 AI 引擎引用你内容的新玩法。最有效的形态是 **FAQ**——问答式的事实陈述，正好是 ChatGPT / Perplexity 回答用户问题时的引用格式。

排版鸭首页放了五个 FAQ：

1. 排版鸭是什么？和同类工具的区别？
2. 复制到公众号后样式会丢吗？
3. 需要注册登录吗？
4. 以后会收费吗？
5. 支持哪些平台？

每个答案都是明确的事实陈述（不是营销话术），并配了 FAQPage 结构化数据——Google 富摘要和 AI 引擎都爱吃这种格式。

### 2.3 品类对比表：事实即说服力

首页放了一张七列对比表：排版鸭 vs Markdown 排版工具 vs 模板富文本编辑器 vs 后台增强插件 vs AI 技能类。

关键设计：**不点名具体产品**，只用品类泛称；表格里全是调研核实过的客观事实（收费模式、登录要求、数据路径、开源与否）。排版鸭列绿色高亮，但其他列也不留空白——诚实比贬低更有说服力。

### 2.4 CI 自动发布：tag 驱动的版本流水线

GitHub Actions 工作流：

```
git tag v0.2.0 && git push origin v0.2.0
   → CI 自动构建（Windows + macOS 双平台）
   → 创建 Draft Release + 上传安装包
   → 人工在 Releases 页面过目 → 点 Publish
```

踩了一个 CI 首跑的经典坑：electron-builder 24 把 `draft: true` 改名成了 `releaseType: draft`，schema 校验直接报错。错误信息把所有合法键名列出来了，一眼定位。

> 💡 **带走的知识点**：CI 的第一次运行永远会踩坑——本地能跑的配置到了 CI 环境会有路径、权限、版本号的差异。解决办法不是"在本地模拟 CI"，而是让错误信息足够好，看一眼就知道该改什么。

## 三、品牌落地

### 3.1 LOGO 全端上线

从 `brand/` 一份源出发，构建时自动栅格化到所有尺寸：

- 导航栏横向 LOGO（`logo-h.webp`）
- 页脚/编辑器方形 LOGO（`logo.webp`）
- 浏览器 favicon（`favicon.png`）
- 桌面应用图标（`icon.png`，窗口 + 安装包）
- 社交分享卡（`og-cover.png`，1200×630 品牌合成图）

以后换 LOGO 只需替换 `brand/` 里的文件，构建自动同步全端。

### 3.2 免费承诺的措辞

首页加了一个承诺区块，措辞经过三轮调整：

第一版：「所有功能永久免费，无会员，无广告，永不拿核心需求做付费墙」——太绝对了，后续出 PRO 版会打脸。

第二版：「核心功能永久免费，增值服务明码标价」——还是暗示了会有付费。

最终版：「所有功能永久免费——MIT 协议写死了这一点。无会员、无广告、无阉割，功能只增不减」+ FAQ 里正面回答「以后会收费吗？→ 不会」。

关键是**用开源协议做结构性保证**：代码在仓库里、MIT 许可证不可撤销，这不是营销承诺，是法律事实。

## 四、Day 5 没做什么

- **自动群发/定时发布**：不做，正式发布永远人工
- **多账号管理**：单号够用，等有真实需求再说
- **自定义域名**：vercel.app 国内可达性时好时坏，但绑域名要备案，Day 6 再议
- **深色模式**：工程量大收益小，暂缓

## 今日总结

| 决策 | 理由 |
|------|------|
| 草稿箱而非自动群发 | AI 管效率，人管判断 |
| 发布前六项体检 | 工具不仅做事，还确认做对了 |
| 静态首页 + 零 JS | SEO/GEO 的基础设施 |
| 品类对比不点名 | 诚实比贬低更有说服力 |
| MIT 协议做免费保证 | 法律事实 > 营销承诺 |
| CI 草稿态 Release | 自动构建 + 人工确认发布 |
