# 不知道写什么？Day 4 给排版鸭装上「选题引擎」

> 「造个轮子！排版鸭 TypeDuck」系列教程 · 第 6 篇
> 前置阅读：Day 3《写不出、写不动、起不来标题？给排版鸭装上大脑》（公众号历史消息可查）

Day 3 结束时，排版鸭已经会写（AI 润色扩写）、会起标题、甚至会自己生成排版主题。但用了一晚上，我发现最痛的问题它还管不着——

**打开编辑器，光标闪烁，脑子里空白。写什么？**

这个问题比"怎么写"更上游。每个持续更新的人都有选题焦虑：热点在哪个平台爆发？别人写什么？我能写什么？配什么图？以前这个流程是：刷半小时微博知乎 → 开十个标签页 → 复制粘贴到备忘录 → 再开 ChatGPT 问「帮我扩展一下」→ 找图另开两个网站。

Day 4 的目标就是把这条断头路接上：**热点、初稿、配图，一个工具里全走完。**

战报：三个新面板（热点选题、配图助手、链接改写）+ 一个线上跨域通道，十次提交、净增约 1500 行。功能和实现都有好戏，往下看。

---

## 一、先走一遍完整流程（今天的正确打开方式）

用今天的真实场景演示，从零到成稿：

1. 点开右侧的 **🔥 热点选题** 面板——微博、知乎、百度热搜、今日头条、36氪、稀土掘金，约 50 个榜单源随时切。今早微博第一条挂着「抖音推出馋猫外卖虚拟点餐」；
2. 这个话题能写。点 **「AI 改写」**——排版鸭自动抓取这条热点的原文，AI 改写成一篇结构全新的初稿，几秒后流式出稿；
3. 初稿里两段不顺眼，选中，工具栏点 **AI 润色**；标题不满意，点标题框旁的 **✨**，五个候选随便挑；
4. 点 **🖼 配图助手**，按「AI 根据文章推荐关键词」给的英文词搜一圈免费图库，挑一张，点 **「封面」**拖动取景裁成公众号的 2.35:1，下载；
5. 回编辑器，**复制到公众号**，去后台粘贴、传封面，人工确认后发布。

以前横跨五六个工具、半小时起步的流程，现在一个窗口。**选题不再是打开文档之后的事，而是打开排版鸭的第一件事。**

## 二、热点面板：约 50 个榜单源，一个 Key 全包

数据源用的是 **allnet.hot** 的聚合 API：免费注册拿一个 Key，就能订阅它聚合的约 50 个热榜——微博热搜、知乎、百度、抖音、B站、36氪、财联社……源列表是运行时拉取的，它加新源我们零改动。

面板交互就三件事：**下拉切源、看榜、动手**。每条热点两个按钮：

- **转选题**：一键建文档，标题就位、原文链接留在开头——留个坑，想写的时候再来填；
- **AI 改写**：不留坑，直接把坑填了。这是今天的主菜，下面单独讲。

工程上留了个心眼：榜单模块做成了**适配器模式**——allnet 是第一个适配器，将来它要是不行了，换一家就是加一个文件的事。为什么要留这个心眼，看完第五节的「死亡名单」你就懂了。

## 三、链接改写：从「一篇别人的文章」到「我的初稿」

这是今天最重头的功能，也是被真实需求逼出来的：热点面板只给你一个标题和链接，正文还得自己看、自己想。于是流程进化成了——

**输入任意文章链接（公众号、博客、新闻都行）→ 自动抓取原文 → 提取正文 → AI 改写 → 输出 Markdown 初稿。**

三个设计决策值得展开：

**① 提取正文比想象中难。** 网页 HTML 里全是导航栏、广告、推荐位，正文只是其中一块。我们用开源的 Readability 算法做通用提取，另给公众号文章（正文在固定的容器里）和知乎、掘金、36氪、少数派这些高频站写了专用路径。提取失败（有些网站内容靠 JS 现渲染，抓回来是空壳）就自动切**粘贴模式**：面板里出现绿色引导链接「↗ 新窗口打开原文，全选复制正文粘贴到下面」——机器搞不定的，人来兜底，永远有路可走。

**② 改写纪律写死在提示词里。** 我们给 AI 的约束是：保留原文全部核心事实、不添加原文没有的内容、用自己的结构重新组织（不做逐句翻译式改写）。这是「编辑部改写」和「洗稿机」的区别：产出的是一份你还要再加工的初稿，不是拿来即发的成品。

**③ 出处永远留痕。** 改写产出的文档，首行自动带 `> 原文：[标题](链接)`。改写别人的劳动成果，注明来源是底线，这个不做成可选项。

## 四、配图助手：免费图库 + AI 荐词 + 封面裁剪

配图是公众号的体力活：开图库网站、想英文关键词（图库英文搜索效果好）、下载、再开修图软件裁成公众号封面的 2.35:1。排版鸭把这条流水线也收编了：

- **双图库**：Unsplash / Pexels，都是免费可商用，注册就送 API Key（延续 BYOK——不，这次连 Key 都不用花钱）；
- **AI 荐词**：点一下，AI 根据你的文章标题生成五个英文图库关键词（比如写「副业」给你 side hustle、home office、laptop workspace），点词块直接搜；
- **三个动作**：缩略图下面「插入」（Markdown 图片语法，写博客的直接用）/「下载」（存原图）/「封面」（重点）；
- **封面裁剪**：画布就是公众号封面的 900×383 比例，拖动取景、滚轮缩放、一键复位，导出 JPG 直接去后台上传。

一个诚实的技术提示也做进了界面：**公众号正文不显示外链图片**。所以「插入」是给博客/文档场景的，公众号正文用「下载后上传」，封面走「封面」按钮。不装作外链能用，是排版工具的基本修养。

## 五、番外一：为什么地址栏能打开，网页里的 AI 却抓不到？

做链接改写时撞上一堵很多人撞过的墙，值得单独讲讲——**CORS，浏览器的跨域安全机制**。

**第一问：链接我在浏览器地址栏明明能打开，为什么页面里的脚本抓不到？**

因为这是两种身份。地址栏访问，你是「用户」，浏览器展示返回内容，没有第三方参与。而网页里的 `fetch` 是「别人家网站的脚本」——浏览器会问目标服务器：「你允许这个来源读你的数据吗？」（看响应里有没有 `Access-Control-Allow-Origin` 声明）。没有，浏览器就把响应扣下，不给脚本。

**第二问：为什么要防这么严？**

防的是这个经典攻击：你登录了网银，浏览器存着你的会话；你随手点开一个恶意网站，它页面里的脚本偷偷请求网银的「查询余额」接口——请求会自动带上你的身份。没有同源策略，余额就被读走了。所以规矩是：**默认禁止跨源读取，除非对方明确声明允许**。

打个比方：地址栏访问是你本人去图书馆借书；跨域 fetch 是你派秘书去借——图书馆要求秘书出示你签发的介绍信（那个 ACAO 声明），没介绍信不借给秘书，但你本人随时能借。

**第三问：那伪造一个「来源」呢？**

网页里伪造不了——`Origin` 是浏览器自己加的请求头，属于 JS 禁止修改的「保留字段」。就算能伪造也没用：拦截发生在**你自己的浏览器**里，裁判跑在你机器上，响应到了它手里它不放行。浏览器之外（curl、Node）确实想写什么写什么，但那不叫绕过 CORS——根本没有浏览器来执行这套规则。我们桌面版的主进程代理走的就是这条光明正大的路。

理解了这三问，排版鸭的**三层抓取通道**就好懂了：

| 层 | 通道 | 谁能用 |
|----|------|--------|
| 桌面版 | Electron 主进程代理（Node，无同源限制） | 装了客户端的 |
| 网页版 | 同源代读函数（自家服务端代读再加 CORS 头） | 部署在线上的 |
| 兜底 | 浏览器直连 | 只对本身开放跨域的站点生效 |

> 💡 **带走的知识点**：CORS 是浏览器的安全模型，不是 HTTP 协议的强制部分。「浏览器不能跨域读 → 让自家后端代读」是标准解法——一个标榜本地优先的工具，最终也还是写了 5 行服务器代码，就为了这堵墙。

## 六、番外二：热榜 API 死亡名单（调研实录）

选热榜数据源前做了一圈调研，11 个候选实测下来，**6 个已经死了**：

| 服务 | 死因 |
|------|------|
| 韩小韩 API | 域名已删除（DNS 查无记录） |
| api.03c3.cn | TLS 证书过期，连接失败 |
| api.qqsuu.cn | 免费接口下线，转型卖接口 |
| PearAPI | 服务已挂 |
| 今日热榜官方数据 API | 503 |
| uapis 旧域名 | 域名迁移，旧地址失效 |

活着的 4 家也各有性格：NewsNow（GitHub 21.4k star，最活跃）公共实例不带跨域头还套着 Cloudflare；uapis.cn 免 Key 又开跨域，但服务年轻、存活史短；DailyHotApi 开源可自部署、57 个源里独有 GitHub Trending，但公共实例已死；天行数据是商业级，但要求十个工作日内实名。

**我们自己的切换实录更说明问题**：早上接的 allnet → 中午调研后眼馋 NewsNow 的源多（还带 GitHub Trending）切了过去，为它做了桌面代理 + 线上函数两层通道 → 晚上权衡再三**又切回了 allnet**——它的 API 跨域全开，网页版直连就行，不依赖任何代理。一天之内两次切换，每次都是十几分钟的事——因为榜单模块从第一天就做成了适配器抽象，换源等于换数据线，不动机器。

> 💡 **带走的知识点**：依赖第三方免费服务的功能，先问一句「它哪天死了怎么办」。答案不是不用，而是**把「换掉它」的成本压到最低**——适配器抽象就是干这个的。顺带一提，那张死亡名单本身就是这么来的：每个死掉的服务，都曾是某个产品的默认选项。

## 七、今天没做什么（同样重要）

- **选题库状态流**（待写/写作中/已发布 + 侧栏分组）：认真讨论过，砍了。攒选题的人自己心里有数，软件里再养一个状态机，用户还得伺候它。等真实需求长出来再说；
- **视频类榜单源**（抖音/B站/快手）：产品定位是文章创作，视频热点转不成文字初稿，不做；
- **无头浏览器渲染层**（治那些 JS 空壳网站）：方案已定（经海外节点中转无头渲染服务），等线上部署后补；
- **网页版国内可达性**：vercel.app 域名在国内时通时断，这是 Day 5/6 要正面解决的问题（大概率是绑自定义域名），今天只记账不动手。

## 今日总结

| 决策 | 理由 |
|------|------|
| 热榜走聚合 API 而非自建爬虫 | 11 家调研 6 家死——爬虫维护成本更高，适配器换源成本更低 |
| allnet 与 NewsNow 一天两换后回到 allnet | 跨域全开 = 网页版零依赖；源的数量让位于链路的简单 |
| 链接改写做三层兜底 | 提取失败必有粘贴模式——机器搞不定的事，给人留路 |
| 改写纪律写进提示词 + 出处强制留痕 | 编辑部改写，不做洗稿机 |
| 配图按「插入/下载/封面」三动作分流 | 公众号不显示外链图，诚实比炫技重要 |

## 下一篇预告：Day 5｜一键发布到草稿箱，正式发布永远人工

人工操作已经压到最低了：选题、初稿、排版、配图都有工具接手。但「搬运」还是手动的——复制、切后台、粘贴、传封面、填摘要，一套动作每天重复。

下一篇（Day 5），把搬运也自动化：**一键发布到草稿箱**——标题、正文、封面、摘要打包推进公众号草稿箱，你在后台预览确认后手动发布。

用它需要在设置里配置公众号的**开发者信息**（AppID / AppSecret，公众号后台的开发设置里获取）——排版鸭的第四次「自带钥匙」：前三次带的是各家 AI 和图库的 Key，这次带的是公众号自己的。

**正式发布保持人工。** AI 生成的内容必须经过人的审核才能面向读者——这既是平台规范，也是创作者对自己内容负责的底线。工具可以替你搬运，不能替你拍板。
