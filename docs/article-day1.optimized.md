# 人人可入门的 AI 开发课 ｜ Day 1：被排版气疯后，48 分钟给自己造了个微信文章排版工具！0行手写代码！

> 「人人可入门的 AI 开发课」Day 1。不写一行代码，只动嘴提需求。DeepSeek 聊需求 + ZCode 写代码 + WorkBuddy 写文章，实测 48 分钟跑通一个公众号 Markdown 排版工具「排版鸭」。附完整提示词，照抄就能复现。

前面 Day 0 我们把三件套装好了——DeepSeek 聊需求、ZCode 写代码、WorkBuddy 写文章。今天动点真格的：用这三件套，实际开干一个公众号 Markdown 排版工具「排版鸭」。

凌晨一点，你刚写完一篇自己挺满意的稿子。

复制到公众号后台，三秒钟，标题没了层次、代码块糊成一坨、配图全乱。你盯着屏幕，第一次想骂人。

然后你花的时间，比写稿还久：手动调字号、行距、颜色、分割线。这活儿我干过不止一次。

所以我给自己定了个小目标：48 分钟，造一个。

从空文件夹，到浏览器里能打开、能写 Markdown、一复制进公众号还不丢样式的工具。我全程没写一行完整的代码，干的事就四样：提需求、拍板、验收、抓 bug。

这篇文章把那 48 分钟里的事都写出来了，翻车的也没藏。更实在的是，流程里每一步，连我发给 AI 的原始提示词，你都能直接抄。不会写代码没关系，照着走一遍，最后落到手里的就是个自己说了算的排版工具：免费、开源、数据全在浏览器里。文末有我做好的线上版，能直接玩。

## 0. 为什么自己造

写公众号的朋友应该都踩过这个坑：用 AI 写完初稿，内容十分钟出来，质量还行。然后你把 Markdown 粘进公众号后台，发现——标题没层次，全一样大的黑字；代码块变成一坨没颜色的等宽字；配图位置乱了；引用块？根本没这玩意。

于是开始手动调。字号、行距、颜色、分割线……一篇两千字，排版花的时间比写还长。

问题卡在中间：AI 给的是 Markdown，公众号编辑器要吃的是富文本。

有人问，市面上 135、秀米、壹伴不是一堆排版工具吗？问得好。它们是为"手动排版时代"设计的——拖组件、调样式，弄完比写文章还累。我要的不是"又一个编辑器"，是"贴进去就能用、所见即所得、数据不出浏览器"的东西。这种需求，现成的没有，得自己造。

> 现成工具解决的是"怎么排得更花"，我要解决的是"别让我排"。这俩根本不是一回事。

## 1. 开工前，先学会"指挥 AI"

很多人以为 AI 编程就是打一句"帮我做个工具"然后坐等收货。试过的都知道，那样出来的东西是个四不像，啥都想做，啥都做不漂亮。

先把我的工作流摊开说，三个工具各管一段（名字你换成自己顺手的就行，流程才是重点）：

```
① DeepSeek —— 聊需求
   把"我想做个排版工具"聊成一份清楚的设计文档：
   功能边界、优先级、哪些砍掉，这一步定

② ZCode —— 写代码
   AI 编程代理，直接在仓库里干活：
   建项目、写代码、跑构建、修 bug、提交 git

③ WorkBuddy —— 写文章
   你正看的这篇，也是 AI 辅助写的：
   素材取自真实开发记录，文风我人工把关
```

三个环节都是我一个人，但角色在变：对 DeepSeek 我是产品经理，对 ZCode 我是技术负责人，对 WorkBuddy 我是编辑。

先细说第一步。我和 DeepSeek 的开场白是这么写的，直接抄就行（方括号里换成你的情况）：

```
我想做一个微信公众号排版工具，请帮我梳理需求。

目标用户：
- [用 AIGC 工具生成文章内容，产出是 Markdown 格式，但对 Markdown 语法并不熟悉]
- [手动排版公众号非常耗时间，经常为调格式头疼]
- [希望免费开源、数据全部留在本地，不想要服务端]

初步想法：
- 输入 Markdown，一键复制成公众号能用的格式
- 要有多个排版主题
- 后面可能加 AI 辅助写作
```

这段提示词没啥文采，但做对了三件事：

1. 讲清给谁用。画像每一行都会变成方案的硬约束："数据留本地、不要服务端"直接把账号体系和云端架构砍了；"不懂 Markdown"逼着产品必须做到贴进去就能用、所见即所得。AI 拿到的是约束，不是一堆形容词。
2. 给足上下文。痛点、技术底线、以后想做啥都摆出来，AI 不用猜。
3. 第一句就要结论。上来就是"帮我梳理需求"，AI 不会跑偏去写营销文案或竞品分析，产出直接冲着能用的东西去。

聊几个回合，"定位是啥、MVP 砍到哪、哪些后置"就都清楚了，最后落成一堆带优先级（P0–P5）的开发文档。这份文档，就是后面 ZCode 开工的根据。

和 DeepSeek 把需求聊透后，扔给 ZCode 的指令只有三句：

> 1. 只做 Web 版 MVP，别碰桌面端
> 2. 本地优先，不要服务端、不要注册登录
> 3. 主题先做 4 �精品，不追求数量

ZCode 给了技术方案（Vue 3 + CodeMirror 6 + markdown-it），我看了没意见，它开工。

AI 时代写代码的第一道坎，不是语法，是把"我要什么"讲清楚。边界越清楚，产出越准。需求在 DeepSeek 多聊十分钟，ZCode 就少返工一小时。

另外，设计文档里原本列了一堆功能，什么 AI 写作、热门榜单、图床、定时发布，我全砍了。MVP 只验证一件事：从 Markdown 到公众号，样式零损耗。这条底线守不住，加再多功能也白搭。

## 2. 最硬的骨头："复制过去样式不丢"

整个工具难就难在这一处。

公众号编辑器有个反人类设定，它把网页样式的三样载体全洗掉：`<style>` 标签、class 属性、外部样式表，只认写在元素身上的内联样式。

```
❌ 粘到公众号 → 被清洗
<style>.title { color: red }</style>

✅ 公众号唯一认的
<h1 style="color: red">标题</h1>
```

所以"一键复制"干的事，就是在 HTML 生成的最后一公里，把所有样式翻成内联的，把所有 class 抹掉。渲染管线长这样：

<!-- 配图位 2：渲染管线流程图 -->

```
Markdown 源码
   ↓ markdown-it 解析
带 class 的 HTML（代码高亮全是 hljs-keyword 这类 class）
   ↓ DOM 后处理：注入内联样式 + 移除所有 class
全内联 HTML ──→ 预览区直接展示（所见即所得）
            ──→ 写入剪贴板 text/html 格式
```

有个地方我觉得做对了：预览区和剪贴板用同一份 HTML。

预览里看到啥，粘到公众号就是啥。不少同类工具翻车就在"预览一套渲染、复制一套转换"，两套逻辑稍有偏差就变形。我们干脆只留一套。

代码高亮最麻烦。highlight.js 输出的着色全是 class，需要一张"class → 内联颜色"的翻译表，而且每个主题一张：浅色主题配 GitHub 配色，暗色主题配 Atom One Dark 配色。这样"极夜黑"主题的代码块、复制到公众号，还是暗色的。

## 3. 翻车现场：AI 写的代码，AI 来审

只讲成功不讲翻车，那是广告。讲个真事。

工具写完，我让 AI 把整个代码库静态审了一遍。报告列了十几个问题，最狠的一个会丢数据。

当时的自动保存逻辑是"防抖 500ms"：停手半秒后存一次。问题出在保存函数里，它存的是"当前打开的文档"。

复现路径：

1. 在文档 A 里打字，触发 500ms 倒计时
2. 手快，第 300ms 切到了文档 B
3. 第 500ms 倒计时结束，存，存的是 B
4. A 的改动从没落盘。这时刷新页面，A 的内容回退

你打的字就这么没了。而且平时完全没感觉，只有"编辑完立刻切走 + 刚好刷新"才触发，这种 bug 最阴，通常上线两周被用户骂了才发现。

修起来不复杂：存谁，在创建定时器那一刻就定死，别等执行时才去找"当前文档"。又加两道保险：切文档前强制存一次，页面隐藏或关闭前再兜底一次。

这个环节想分享的观点只有一个：

> AI 写的代码也要审，而且 AI 可以审 AI。

开发是 AI 写的，审查是 AI 做的，修复还是 AI 做的，一轮下来 9 个问题清零。人现在就干三件事：看懂报告、判断轻重、决定修不修。

"写代码"正在变成"审代码"。这活儿，每个想自己捣鼓点东西的人都值得练。

## 4. 上线：3 分钟，一个能点的链接

代码写完只能算半成品，能被别人点开的链接才是产品。

部署用的 Vercel，免费：导入 GitHub 仓库、指定子目录、点部署，前后 3 分钟。之后每次 push，线上版自动更新。

## 5. 48 分钟背后的三件事

**1. 工具类产品的壁垒不是功能，是顺滑。**

这 48 分钟大部分时间花在一件事上：让"复制 → 粘贴"这条路不掉链子。功能以后能加，掉链子的第一印象没有第二次机会。

**2. AI 编程时代，人做的东西变了。**

五年前这个工作量按"人日"算，今天按"分钟"算。变的不是我突然会写代码了，是流程变了：需求裁剪、约束表达、方案拍板、结果审查，人现在就做这四件事。

**3. 不用背八股文，也不用会算法，也能拥有个为自己定做的工具。**

这 48 分钟真正用到的能力，就是把需求讲清楚、判断方案好坏、验收结果，传统编程那些"硬功夫"一样没上。会不会写代码和能不能拥有自己的软件，这两件事第一次脱钩了。
